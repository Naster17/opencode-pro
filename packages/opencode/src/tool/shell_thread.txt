Manage background shell commands. Use this when a command should continue running while you perform other work.

Actions:
- start: starts a background shell command and returns a threadID. Requires command and description. Pass wait:true with optional timeoutMs to start and wait in one call.
- read: reads output from a thread. Provide threadID. Use since with the cursor returned by previous reads to fetch only new output.
- list: lists shell threads for the current session.
- stop: stops a running thread. Provide threadID.
- wait: blocks the tool call until threads complete instead of polling with sleep/read loops. Provide threadID or threadIDs with mode any|all (default all), optional timeoutMs (default 30000, max 300000), and optional notify:true to post a synthetic followup message when still-running threads finish after the timeout.

Do not use wait on servers, watchers, tail -f, or other never-ending commands; use read/stop for those.

Use normal shell for short commands. Use shell_thread for long-running servers, watchers, builds, or diagnostics that should be checked periodically.
